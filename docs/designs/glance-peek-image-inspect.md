## Product Thesis

Glance is the macOS observation layer for digital files:

> No matter where a file path appears, the user can immediately understand what it is without leaving the current workflow, then enter a focused inspection and comparison experience when more detail is needed.

The problem is not that files cannot be opened. The problem is that checking a file forces the user to leave the current context, locate another app, and reconstruct where they were.

## Target Behavior

Glance has two deliberately different depths:

- **Peek** confirms identity and content. It is broad, fast, non-activating, and supports the existing media and document types.
- **Image Inspect** examines details. It is an activating image-specific workspace with Focus, Browse, and Compare states.

The transition is progressive:

```text
path or URL in any app
  -> Option + Space
  -> Peek
  -> click content
  -> Image Inspect
  -> Focus / Browse / Compare
```

## Product Principles

- Peek never steals focus. Editing, navigation, and detailed controls belong in Inspect.
- The first deep workspace is image-only. Existing viewers for video, PDF, Markdown, text, and web content remain available but do not expand in this phase.
- Correct object identity matters more than adding file formats. A fast preview of the wrong `result.png` is a failed preview.
- Entry intent determines depth. Hotkey input starts with Peek; explicit Finder opening starts with Inspect.
- Loaded data travels forward. Moving from Peek to Inspect must not repeat path resolution, network transfer, or image decoding.

## Three-Second Peek Contract

The primary metric is **time to confidence**: the time until the user knows what object Glance resolved and whether it is the intended object.

| Time | User outcome | Required behavior |
| --- | --- | --- |
| 0-100ms | The command was received | Detect `Option + Space`, create a request identity, and show a stable Peek shell without changing focus or selection. |
| 100-180ms fast path | Glance understands the selection | When AX responds quickly, extract selected text, identify paths, and show object identity. Otherwise keep the identity area as a fixed-height skeleton. |
| 180-400ms fast path | The object is visually recognizable | Resolve an explicit local path or URL and show the first useful image frame. A still-pending extraction changes the status to `Reading selection` after 250ms. |
| 400-800ms fast path | The object is trustworthy | Add filename, middle-truncated path tail, source, dimensions, format, and file size without changing panel geometry. Slow paths continue with named `Reading selection`, `Resolving path`, or `Loading image` states. |
| 800-3000ms | The user decides | The user observes, presses the hotkey again to close, selects another path to replace the Peek, or clicks the content to enter Inspect. |

At three seconds the user must be able to answer:

1. What am I looking at?
2. Where did it come from?
3. Is it the object I intended?
4. Should I dismiss it or inspect it?

Showing a panel or finishing a decode is not success if these questions remain unanswered.

## Peek Interaction Model

### Lifecycle

```text
hidden + hotkey                         -> open Peek
loading + hotkey                        -> cancel and close
visible + same selection + hotkey       -> close
visible + new selection + hotkey        -> replace content in the same Peek
visible + unreadable selection + hotkey -> close
Inspect visible + new selection         -> preserve Inspect; open or replace Peek
Escape while Inspect is active          -> close the topmost Inspect state
```

The current implementation closes any visible preview before reading the next selection. This must change so users can inspect consecutive CLI outputs without performing a close-open sequence.

For a visible, fully loaded Peek, the second hotkey performs a fast AX-only read with a short budget of approximately 50ms. Compare normalized selection text and source application identity with the active `PreviewRequest`. Normalization trims leading/trailing whitespace and trailing newlines before comparison; it does not otherwise rewrite path content.

- the same value closes Peek;
- a different non-empty value replaces Peek;
- empty, unavailable, or timed-out extraction closes Peek;
- this decision does not use clipboard fallback because synthesizing Copy would make toggle behavior slow and invasive.

Peek does not respond to Escape. A non-activating panel cannot receive it without globally intercepting a key that terminal users need for Vim, `less`, and `fzf`. Peek closes through its activation shortcut or visible close control.

### Activation

- Recommended default shortcut: `Option + Space`, with remapping available during onboarding and in Preferences.
- A modifier-only shortcut may remain as an advanced preference. If retained, it activates on the configured modifier's up-to-down transition, as the current implementation does; the UI warns that normal Option combinations may trigger it.
- Detect common registered conflicts where possible and explicitly warn when `Option + Space` is already used. Raycast, Alfred, and the macOS non-breaking-space input behavior make remapping a first-class path, not an advanced recovery path.
- In combo mode, consume Space key-down, repeats, and matching key-up as one balanced gesture. In modifier-only mode, pass all non-modifier events through.
- The event-tap callback only updates locked state, marks whether an event is consumed, and dispatches work asynchronously. It never extracts selection, resolves paths, builds UI, or blocks keyboard delivery.
- The Peek uses a non-activating panel and must not call `makeKey()`.
- Clicking content is the explicit handoff at which Glance may activate and open Image Inspect.

### Click and Activation

- The image content view and close control accept the first mouse click while the window is inactive, so one click performs the action rather than merely activating Peek.
- Clicking image content opens Inspect. Clicking the close control closes Peek. Clicking passive identity chrome does nothing and does not activate Glance.
- Snapshot the restore target immediately before the content click activates Glance. If the user changed foreground apps while Peek was visible, Inspect returns to the app they actually left, not the app that originally opened Peek.
- If an Inspect window remains open while the user has returned to another app and invokes the hotkey, Inspect keeps its existing session and a non-activating Peek appears on the cursor's screen. Opening Peek never activates Glance or raises Inspect.
- Clicking that new Peek replaces the existing Inspect window's session with the new Peek session and brings the same Inspect window forward. V1 maintains one Inspect workspace rather than opening competing Inspect windows.

### Window Placement

- Peek uses `ScreenManager.centeredFrame` on the cursor's current screen and remains fully inside `visibleFrame`.
- Inspect opens on the same screen as the Peek that launched it, or on the cursor's screen for a Finder launch, and uses `ScreenManager.contentFrame` to shrink and clamp its initial size.
- Neither surface anchors directly to the text selection or mouse position in a way that can place it off-screen.

### Passive Lifetime

- Peek has no inactivity timeout and does not close merely because the foreground app changes.
- Peek closes when its source application terminates, the system sleeps or locks, or the user disables Glance.
- Moving between macOS Spaces does not implicitly close Peek; the existing all-Spaces panel behavior remains.

### Presentation

- Content owns most of the surface.
- The title is the filename or URL identity, not the word `Glance`.
- Show a path tail and source context, for example `Warp · ~/work/app/outputs`.
- Show dimensions, format, and size when available.
- Keep layout stable while metadata arrives.
- Do not expose login in Peek chrome.
- Do not show a spinner immediately. Show a stable skeleton first; label the operation as loading only after roughly 250ms.

### Single, Group, and Ambiguous Semantics

The number of resolved URLs must not determine intent by itself. Every request has one of three meanings:

- **Single object:** one explicit path or URL; show one primary preview.
- **Explicit group:** the selected text contains multiple explicit paths; show a thumbnail grid.
- **Ambiguous object:** one token resolves to multiple candidates; show the highest-confidence object and expose alternative candidates separately.

An ambiguous token must never become a gallery merely because global search returned many matches.

### Post-Slice: Explicit Group

- Use a stable thumbnail grid for 2-6 items.
- Load tiles independently; one failure must not block other tiles.
- For more than six items, show the first five plus a `+N` summary tile.
- Clicking a tile sends the full group to Inspect and focuses the clicked item.

### Post-Slice: Ambiguous Object

- When the best candidate exceeds the confidence threshold, display it with the reason it ranked first and show an affordance such as `2 other matches` rather than rendering all matches as content.
- When no candidate exceeds the threshold, do not preview a guessed object. Show an unresolved state whose next action opens the candidate list.
- A future resolution cache must include source application and workspace/current-directory context. A global `token -> URL` cache can make one wrong guess persist indefinitely.

## Error Contract

Errors must distinguish at least:

- no selected text;
- selected text contains no recognized path;
- recognized local path does not exist;
- multiple candidates exist but none exceeds the confidence threshold;
- permission denied;
- remote request failed;
- file exists but cannot be rendered.

Every error states what Glance understood and the next available action. A generic `No image or video found` response is insufficient.

## Image Inspect Contract

Image Inspect is a persistent, activating image workspace. It is not a larger Peek and does not absorb the existing PDF, Markdown, text, web, or video viewers during this phase.

### States

- **Focus:** inspect one image in detail.
- **Browse:** inspect one focused image while retaining a temporary group.
- **Compare:** compare exactly two selected images.

Three or more simultaneous images form a review grid or Browse state, not a precision Compare state.

### First Ten Seconds

| Time | User outcome | Required behavior |
| --- | --- | --- |
| 0-150ms | Inspect opens | Reuse Peek data, activate Glance, focus the clicked item, and avoid a second loading cycle. |
| 150-500ms | Identity is stable | Show the main image, filename, item position, and zoom mode. |
| 0.5-2s | Overall image is understood | Default to Fit-to-View with quiet chrome and maximum useful canvas. |
| 2-5s | A detail is examined | Provide pointer-centered zoom, pinch zoom, drag pan, and Fit/100% toggling. |
| 5-10s | The next task is chosen | Navigate the group, open metadata, enter Compare, or close and return to the source app. |

### Controls

- Pointer-centered wheel and pinch zoom.
- Drag to pan.
- Double-click toggles Fit-to-View and 100%.
- `Command + 0` fits the image.
- `Command + 1` selects 100%.
- Left and Right arrows navigate the group.
- `Command + I` toggles image information.
- Escape exits Compare first, then closes Inspect.
- A temporary chrome-hiding action may be added after the core interaction is stable.

### Filmstrip

- A single-image session has no filmstrip.
- A group session shows the filmstrip on entry so group context is discoverable.
- It fades after approximately three seconds of inactivity or as soon as zoom/pan begins.
- It returns when the pointer reaches the bottom edge, navigation keys are used, or Compare needs a B selection.
- It overlays the canvas. Showing or hiding it must not resize the viewport or change Fit scale.
- Edge-triggered reappearance is suppressed while zooming, panning, or dragging.

### Closing

- Closing Compare returns to the prior Focus or Browse state.
- Closing Inspect returns to the application that was active before Inspect opened.
- Closing Inspect after a Peek transition does not resurrect Peek.
- Glance should not attempt to reconstruct another application's text selection.

## Post-Slice: Finder Entry Rules

| Input | Default result |
| --- | --- |
| One image opened with Glance | Focus |
| Exactly two images opened together | Compare |
| Three or more images opened together | Browse |

These rules use the intent already expressed by the Finder selection and avoid another modal question.

## Post-Slice: Compare V1

Compare V1 includes:

- two-image left/right view as the default;
- synchronized zoom and pan;
- a draggable reveal slider using the same A/B pair;
- a metadata difference summary.

Blink, opacity overlay, pixel heat maps, and comparison of more than two simultaneous images are deferred.

### Viewport Alignment

- Same pixel dimensions default to pixel-aligned synchronization.
- Different dimensions default to normalized relative synchronization.
- Unlocked mode permits independent viewports.
- The interface names the active alignment mode and never implies pixel alignment when it is not present.

Normalized synchronization stores zoom relative to each image's Fit scale and stores center coordinates as percentages of image width and height. Switching between side-by-side and slider preserves A/B identity, zoom, and center.

### Difference Summary

Show differing fields first and collapse equal fields. Initial deterministic fields are:

- pixel dimensions and percentage change;
- aspect ratio;
- file size and percentage change;
- format;
- color space;
- bit depth;
- alpha presence;
- creation and modification timestamps;
- EXIF values when they can be read reliably.

V1 reports facts. It does not claim that one image has better quality or worse compression.

## Product Entry Matrix

This matrix describes the intended product after the post-slice group and Finder phases. The first vertical slice implements only the first row for explicit image paths and URLs.

| Source and selection | Default surface |
| --- | --- |
| One path in CLI, chat, code, or a document | Single-object Peek |
| Multiple explicit paths in text | Explicit-group Peek |
| One ambiguous filename with several matches | Highest-confidence Peek plus candidate notice |
| One image from Finder | Image Inspect Focus |
| Exactly two images from Finder | Image Inspect Compare |
| Three or more images from Finder | Image Inspect Browse |
| Click one tile in a multi-image Peek | Image Inspect Browse with that item focused |

## Architecture

Use a dedicated image session rather than expanding the single-object `ContentPanel` or designing a generic future-media framework.

```text
PreviewRequest
  sourceContext
  selectionText
  semanticKind: single | explicitGroup | ambiguous
  resolvedItems
  resolutionEvidence
  requestID

ImageInspectSession
  items
  focusedIndex
  mode: focus | browse | compare
  compareSelection: A/B
  viewportState
  comparisonStyle: sideBySide | slider
  inspectorVisible
  sourceContext
```

Ownership rules:

- `AppDelegate` coordinates requests and transitions but does not own view state.
- `PreviewPanel` renders Peek only.
- `ImageInspectSession` is the sole owner of image-group, focus, comparison, and viewport state.
- `ImageInspectWindow` renders and mutates the session.
- A reusable image viewport component owns pointer-centered zoom and constrained pan.
- Existing `ImageLoader`, `ScreenManager`, and `PanelStyle` remain shared infrastructure.
- The loaded image payload is transferable from Peek to Inspect.

## First Vertical Slice

The first shippable slice is:

> In a CLI or IDE, select one explicit local image path or complete image URL, press `Option + Space`, see a non-activating trustworthy Peek, click the image to enter Inspect without reloading, inspect details, then close and return to the original app.

### Included

- explicit local absolute image paths;
- complete HTTP(S) image URLs;
- hotkey input always opening Peek first;
- same-selection toggle close and new-selection replacement;
- non-activating Peek;
- filename, path tail, dimensions, format, and size;
- loaded-image transfer into a dedicated single-image Inspect session;
- Fit, 100%, pointer-centered zoom, pan, and basic information;
- return to the previously active application on close;
- local-only diagnostic counters and timings.

### Deferred

- terminal current-directory inference;
- ambiguous filename search redesign;
- multi-image Peek grid;
- Finder document association;
- Compare;
- complete EXIF support;
- login, synchronization, and history changes;
- new deep behavior for non-image formats.

### Request Lifecycle

- Every activation creates a monotonically newer request identity. UI callbacks verify the identity before changing Peek or Inspect.
- Replacing or closing a loading Peek cancels selection, resolution, and fetch work when the underlying API permits cancellation; late callbacks are always ignored.
- Clicking a still-loading Peek transfers the same request and progress to Inspect rather than starting a second fetch. Inspect may show the existing progressive state until the image arrives.
- Closing Peek may retain completed decoded images in the existing bounded memory cache, but does not keep an otherwise unused network request alive.
- A remote fetch has an explicit timeout and byte limit. Exceeding either produces a specific recoverable error.

## Implementation Sequence

1. Define `PreviewRequest`, transferable loaded image data, and `ImageInspectSession` state.
2. Make the hotkey route all image results through Peek and remove single-image direct opening from this entry path.
3. Make Peek truly non-activating and implement same-selection close versus new-selection replace.
4. Simplify Peek identity chrome and make loading/error states progressive and stable.
5. Implement `ImageInspectWindow` and a reusable pointer-centered image viewport.
6. Transfer an already loaded image from Peek to Inspect and restore the prior active app on close.
7. Add local-only timing and outcome diagnostics.
8. Validate the first slice across Terminal, Warp/iTerm where available, Cursor/VS Code, a browser, local/remote URLs, spaces, and Chinese paths.
9. Add explicit-group Peek and Finder entry rules.
10. Add Compare V1 on the same `ImageInspectSession` model.

## Slice 1 Success Criteria

- Hotkey feedback: p95 below 100ms.
- For fast AX extraction, explicit local image first useful frame: p50 below 180ms and p95 below 400ms. `Fast AX` means selected text returns within 100ms of hotkey key-down. A useful frame is decoded image content on screen, not a skeleton or placeholder.
- Extraction, path resolution, and image loading timings are measured separately so a slow source application is not hidden inside one aggregate number.
- Peek changes the foreground application or selection: 0 occurrences.
- Peek-to-Inspect transition with an already loaded image: below 150ms, with no second fetch or decode.
- Every Slice 1 failure has a specific category and next action.
- Same-hotkey close follows the fast-read decision tree correctly in the validation matrix.

## Post-Slice Targets

- Explicit context-aware relative-path resolution: p95 below 500ms.
- Global ambiguous search candidate response: p95 below 1500ms.
- Wrong top-ranked match for a context-resolvable token: below 1% in the validation corpus.
- Compare mode switching preserves A/B identity and viewport state and completes below 100ms.

Local-only diagnostics should count trigger attempts, successful previews, unrecognized selections, missing files, time to first useful pixels, Inspect transitions, and manual candidate corrections. Do not record full selected text.

## Approaches Considered

- Extend `ContentPanel`: rejected because its single-URL state couples image interaction to web, text, Markdown, and PDF behavior.
- Build a generic media session framework: rejected because non-image deep workflows are not yet validated.
- Dedicated image session: selected as the smallest architecture that supports the first slice and the later Focus/Browse/Compare state flow.

## Risks and Edge Cases

- A non-activating panel may still cause focus changes if `makeKey()` or activation calls remain in the path; validate actual foreground application and first responder, not only window style.
- `Option + Space` handling must consume a balanced key sequence without affecting unrelated Option combinations. Shortcut collision testing is part of onboarding validation.
- A new activation arriving while extraction, search, or download is in flight needs request IDs and cancellation so stale callbacks cannot overwrite newer content.
- Remote image redirects, authorization failures, very large images, animated images, color profiles, and corrupt files require bounded work and explicit errors.
- Existing selection extraction can spend up to one second on AX and another 250ms on clipboard fallback. The UI must expose progressive state, and later work should measure per-source latency before changing timeouts.
- Full Disk Access is optional and must not block initial onboarding. Request it only after a relevant protected-location operation fails.
- History should not persist full selected text by default because selections may contain unrelated terminal, code, or chat content.

## Remote Fetch Policy

- Use an ephemeral request without browser cookies or stored credentials.
- Follow at most five HTTP redirects and preserve only HTTP(S) destinations.
- Validate response status and image-compatible content before decoding.
- Apply bounded connection, response, byte-size, pixel-count, and decode limits; exact values should be set from measurements during Slice 1 rather than guessed in this document.
- Permit loopback and private-network image URLs because local development is a core CLI use case. Never attach ambient credentials to them.
- Authentication failures offer to open the URL in the user's browser; Glance does not copy browser sessions into the fetcher.

## Distribution

The existing signed beta DMG remains the distribution channel. The first vertical slice should be exercised by a small test group drawn from high-frequency image and path workflows before broad distribution. This phase does not add account requirements or cloud telemetry.

## Validation Assignment

Before implementing ambiguous path context, collect 30 real examples from daily work across terminal output, code, chat, and Finder. Record the source app, exact path shape, intended file, current workaround, and whether the task was quick confirmation, detailed inspection, browsing, or comparison. Do not collect surrounding sensitive text.

## What I Noticed

- The strongest signal was the user's own repeated CLI need combined with a separate need to inspect image details and compare images.
- The user accepted a narrower deep workspace while preserving the existing broad preview surface, which keeps the product thesis coherent without deleting working capabilities.
- The user consistently chose predictable defaults: explicit `Option + Space`, same-key toggle, click-to-Inspect, thumbnail-grid group confirmation, and left/right Compare.
