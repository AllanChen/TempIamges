## 1. 结论先行

Glance 采用两条独立的收费线：

- **Pro 买断**：一次付费，解锁本地工具箱（转换、压缩、导出、复制图片、编辑、Base64 等）；图片 OCR 识别和复制文字免费。价格、首发价、更新续购价都在后台配置。
- **点数**：云端 Widget 按次扣点，充值获得，长期有效。

用户看到的版本只有三种状态：

| 状态 | 能做什么 |
|---|---|
| 试用中（首次启动起 14 天） | 全部功能；云端 Widget 用点数 |
| Pro | 全部功能，永久；云端 Widget 用点数 |
| 免费版（试用结束且未购买） | 拿图、看图、对比、截图、OCR 识别与复制文字；云端 Widget 用点数 |

划分只看一条规则：

> **把图拿进来、看、比、识别并复制图片文字，免费；用 AI 改，按点数；其他本地加工属于 Pro。**

体验原则：

1. **首次启动零登录。** 试用从首次启动自动开始，不需要账户。只有用到云端 Widget 或购买时才登录。
2. **试用结束不丢东西。** 文件、结果、历史和点数都保留，购买 Pro 后立即恢复全部功能。
3. **Widget 不弹每次确认。** 价格显示在菜单里，余额够就直接提交，排队中可撤销，系统失败自动退点。
4. **付款流程一步到浏览器收银台。** 删除 App 内与收银台重复的「确认订单」页。
5. **余额不足就地充值。** 付款后回到同一个任务，可以选择到账后自动提交。

## 3. 原稿问题回顾

以下问题是本版修改的依据，按影响排序。

1. **免费范围在稿件里含糊。** 稿件只列了几项 Pro 功能，没有说清免费版剩下什么。本版按 D14 用一条规则划分：拿进来、看、比免费；AI 改按点数；本地加工属于 Pro。
2. **首屏主按钮要求登录。** 本版改为首次启动零登录，试用自动开始。
3. **每次跑 Widget 都弹费用确认。** 本版改为默认直接提交，可撤销。
4. **购买 Pro 要确认两次订单。** App 内确认页和收银台内容重复，本版删除前者。
5. **余额不足恢复要五步，回来还要再确认。** 本版压缩为一个 sheet。
6. **充值包线性定价，没有大包激励。** 本版按 D5 使用带赠送的三档。
7. **稿件与实现不一致。** 赠送点数、邮箱登录方式、退点规则三处，本版统一以本 PRD 为准。
8. **支付异常只覆盖 Pro。** 本版覆盖所有订单。

## 4. 目标与非目标

### 目标

- 首次启动到看第一张图，零登录、零付费提示。
- 用户能用一句话理解收费：「Pro 一次买断解锁全部功能；云端 Widget 按次用点数。」
- 试用结束后，用户能清楚知道哪些操作被锁、怎样恢复。
- 余额充足时，从点击付费 Widget 到任务提交只需 1 次点击。
- 余额不足时，从点击 Widget 到任务提交不超过 4 步。
- 每一笔到账、扣点、退点、购买都可以在账户里查到。
- 系统原因导致没有结果时，不收用户的点数。
- 所有价格可在后台修改，修改后无需发版。

### 非目标

- 订阅制、自动续费。
- 发票、企业采购、团队钱包、兑换码。
- Mac App Store 内购。
- 人民币、美元以外的币种（见 10.3）。

## 6. 核心流程：点数

### F1：首次使用与登录

```
首次启动 Glance → 试用自动开始，全部本地功能可用（无登录）
              → 第一次点击云端 Widget
              → 当前窗口弹出登录 sheet（Google / 邮箱验证码），文案「登录送 100 点」
              → 登录成功，sheet 关闭，自动继续刚才的操作
```

- 首次启动只显示一次轻提示：「已开启 14 天完整试用」，不弹窗。
- 图片、参数在登录过程中原样保留。
- 赠送到账用 toast 告知：「已到账 100 点」。
- 免费 Widget 也需要登录，因为任务和结果要绑定账户；文案不提点数。

### F2：使用 Widget 与扣点

```
Inspect 窗口 → 菜单里看到「高清放大  8 点」
            → 点击
            → 余额足够：立即提交，toast「已提交 · 扣 8 点 · 撤销」
            → 任务完成：结果进入对比视图
```

确认策略：

| 场景 | 行为 |
|---|---|
| 账户第一次运行付费 Widget | 弹一次说明：「点击即扣点；系统失败自动退回；排队中可撤销」。之后不再弹 |
| 单价 ≤ 确认阈值（后台定义，D11） | 直接提交 |
| 单价 > 确认阈值 | 弹费用确认：本次费用、当前余额、提交后余额 |
| 已提交、尚未被 Worker 领取 | toast 显示「撤销」，撤销即取消并全额退点 |
| 价格已变化（`price_changed`） | 弹确认并展示新价格，用户确认后按新价提交 |

确认阈值是后台配置项，客户端随定价配置一起拉取，修改无需发版。

### F3：余额不足就地充值

```
点击 Widget → 余额不足
          → 当前窗口弹出充值 sheet：
              「高清放大需要 8 点，当前 2 点」
              三个充值包（默认选中能覆盖本次费用的推荐包）
              支付方式：微信支付（人民币） / 银行卡（美元）
              [✓] 到账后自动提交本次任务
              [前往支付]
          → 浏览器打开 Pancake 收银台
          → 付款完成，跳转到 Glance 返回页，再唤起 App
          → sheet 显示「等待到账…」
          → 到账：已勾选则直接提交；未勾选则显示「确认提交 · 8 点」
```

- 余额不足时不创建任务、不扣点，沿用现有服务端逻辑。
- 「到账后自动提交」由用户在付款前明确勾选，只对这一次任务生效。
- 用户关闭 sheet 后，待提交任务保留到窗口关闭；钱包里显示「有 1 个任务等待提交」。
- 客户端原有的余额预检（`WidgetTaskClient`）改为弹出此 sheet，不再只报错。

### F4：钱包与主动充值

入口：托盘里的余额行、偏好设置的账户页。

钱包页包含：

- 余额（大号）+「长期有效 · 多台 Mac 共享」
- 充值包三选一、支付方式、「前往支付」
- 流水列表：时间、类型标签、名称、变动数额
- 类型标签：赠送 / 充值 / 购买赠送 / 消耗 / 退回 / 调整
- 底部说明：「本地功能不消耗点数」

### F5：失败退点与取消

| 情况 | 是否退点 | 用户看到 |
|---|---|---|
| Worker 回报失败，无可用结果 | 自动全额退 | 任务中心「失败，已退回 8 点」，toast 提示一次 |
| 超过最大重试次数（3 次，D12） | 自动全额退 | 同上 |
| 排队超过最长等待时间（30 分钟，D12） | 自动全额退 | 同上 |
| 用户在排队中取消 | 全额退 | 「已取消，已退回 8 点」 |
| 用户在执行中取消 | 不退（D13） | 取消前确认：「任务已开始执行，取消后不退回 8 点」 |
| 有结果但用户不满意 | 不自动退 | 任务详情提供「反馈问题」，管理员可手动调整 |

内部重试、Worker 重新领取不重复扣费，现有实现已经保证。

## 7. 核心流程：Pro

### F6：试用与试用结束

```
首次启动 → 试用自动开始（14 天，全部功能）
        → 剩余 3 天：标题栏旁出现「试用剩余 3 天」角标，点击打开 Pro 介绍 sheet
        → 剩余 1 天：再提示一次
        → 试用结束：下一次启动显示一次 sheet
             「试用已结束。查看、对比、截图和 AI Widget 继续可用；转换、导出等本地工具需要 Pro。」
             [购买 Pro]  [继续查看]
        → 免费版中点击任何被锁的操作：弹出 Pro 介绍 sheet（见 F7）
```

规则：

- 试用期从首次启动开始算，与是否登录无关。
- 试用记录写在 Keychain 并带设备标识，重装应用不会重置试用。登录后，服务端按账户再记一份；同一账户在任何设备上开过试用，以最早的开始时间为准。
- 购买 Pro 后试用状态立即作废，不再显示剩余天数，也不会把剩余试用天数累加到任何地方（D9）。
- Pro 被退款后，账户回到免费版，不会重新获得试用。
- 试用结束不删除任何文件、历史、结果和点数。

### F7：购买 Pro

```
「查看 Pro」或「购买 Pro」
  → Pro 介绍 sheet：价格（首发价时显示原价划线和截止日）、权益、
     包含 12 个月更新、2 台 Mac、赠送 100 点
     支付方式：微信支付（人民币） / 银行卡（美元）
     [购买 Pro]
  → 未登录：先登录，成功后回到此 sheet
  → 浏览器打开 Pancake 收银台
  → 付款完成 → Glance 返回页 → 唤起 App
  → App 内「Pro 已激活」：授权、赠送点数、当前余额
```

- 删除原稿的 App 内「确认购买 Pro」页。商品、金额、账户在收银台显示一次即可。
- 已购用户不再显示购买入口，改为显示授权状态。

### F8：设备管理

| 状态 | 用户看到 | 操作 |
|---|---|---|
| 名额未满 | 登录即激活当前 Mac | — |
| 名额已满 | 「设备名额已用满」，列出已激活设备和最近使用时间 | 释放某台设备后激活当前 Mac |
| 已释放 | 被释放的 Mac 下次联网时回到免费版，本地文件保留 | 在该 Mac 重新登录即可再次激活 |

- 授权凭证由服务端签名，客户端缓存。离线时凭证在 30 天有效期内可继续使用 Pro（D10）；超过 30 天未联网，Pro 功能暂停，联网后自动恢复。
- 释放设备不影响点数和文件。
- 每 30 天最多释放 3 次设备，超过后提示联系支持。

### F9：功能更新期结束与续购（最后一期开发）

规则（采用 Sketch 式买断）：

- 每个 Glance 版本带发布日期。
- 授权的「更新截止日」不早于版本发布日期时，该版本可使用 Pro。
- 更新期结束后，用户可以一直使用截止日之前发布的版本。安全修复版本不受限制。
- 续购从付款当天起算 12 个月，不补收空档期，不自动续费。

界面：

- 安装了更新截止日之后发布的版本时，Pro 功能入口提示「此版本需要续购更新」，提供「续购一年更新」和「下载可用的最后版本」。
- 账户页显示更新截止日。

## 8. 支付异常与退款

### 8.1 支付异常（所有订单通用）

Pancake 没有取消回跳地址。用户关闭收银台后不会回到 App，会话到期后订单自动作废，不扣款。客户端需要自己处理。

| 状态 | 触发 | 用户看到 | 操作 |
|---|---|---|---|
| 等待付款 | 已打开收银台 | sheet「请在浏览器完成支付」 | 「我已完成支付」「放弃本次支付」 |
| 等待到账 | 回到 App，服务端未收到回调 | 「正在确认付款结果，请勿重复支付」 | 自动轮询；「重新查询」 |
| 到账超时 | 超过 2 分钟仍未确认 | 「付款确认较慢。若已扣款，会自动到账」 | 「联系支持」并附订单号 |
| 会话过期 | 收银台会话超时（默认 30 分钟） | 「订单已过期，未扣款」 | 「重新支付」 |
| 微信支付不可用 | 买家本月在本商户的微信支付累计超过 ¥1,000 | 收银台不显示微信支付 | 客户端提示改用美元银行卡支付 |

到账、激活只以服务端收到并验签的 Webhook 为准，不以浏览器跳转为准。

### 8.2 退款政策（D8）

总原则：14 天全功能试用已经给了用户充分的评估时间，所以退款以「没有实际消费」为条件，同时 14 天内对 Pro 保持宽松，减少拒付。拒付对 Merchant of Record 渠道的账户风险远大于一次退款。

| 商品 | 可退条件 | 退款后处理 |
|---|---|---|
| Pro 买断 | 付款后 14 天内，无需理由，全额退款 | 撤销 Pro 授权，释放所有设备，账户回到免费版；收回购买赠送的 100 点，已用掉的部分记为负余额（见 8.3） |
| 充值包 | 付款后 14 天内，且该订单的点数一点都没用过，全额退款 | 收回该订单的全部点数 |
| 充值包，已部分使用 | 不退款 | 系统原因失败的任务已经自动退点，不再退钱 |
| 功能更新续购 | 付款后 14 天内，全额退款 | 更新截止日回退到续购前 |
| 重复付款 | 任何时间，全额退款 | 只保留一笔订单的权益 |
| 支付后未到账、无法使用 | 任何时间，全额退款或补发 | 由你在后台选择 |

**「充值包没用过」的判断**：发起退款时，当前余额不少于该订单到账的点数，就视为没用过。这个规则简单、可由系统自动判断，不需要逐笔追踪点数来源。

**退款入口**：

- 用户通过客服邮箱或 App 内「申请退款」提交，附订单号。
- 你在后台审核后，由后台调用 Pancake 退款工单接口发起退款。
- 只有收到 Pancake 的 `refund.succeeded` 事件后，才撤销权益或扣回点数。`refund.failed` 时订单标记为退款失败，权益保持不变，后台显示待处理。
- 退款政策页面放在官网，并在收银台展示（Pancake 要求）。

### 8.3 余额不足以扣回时

允许余额暂时为负，同时冻结付费 Widget。管理员可在后台处理。

## 9. 计费规则汇总

| 规则 | 说明 |
|---|---|
| 扣点时机 | 任务被服务端接受时扣点，与创建任务在同一事务 |
| 价格来源 | 服务端当前配置，客户端传入的价格只用于校验 |
| 防重复扣费 | 相同 `Idempotency-Key` 只扣一次 |
| 退点 | 系统失败、过期、排队中取消，按任务记录的原价全额退，每个任务最多退一次 |
| 余额下限 | 正常消费不允许为负；退款扣回可以为负（见 8.3） |
| 到账 | 以验签后的 Webhook 为准，同一订单只到账一次 |
| 赠送 | 新用户赠送每个账户一次，并且每台 Mac 只发放一次（按设备标识）；购买赠送每个账户一次 |
| 待付订单 | 同一账户同一商品只保留一笔待付款订单；重复点击支付打开同一笔订单 |
| 下单校验价格 | 创建 Pro、续购、充值订单时带上用户看到的价格；价格已变化则不创建订单，提示用户按新价确认 |
| 设备释放 | 每 30 天最多释放 3 次设备（后台可配置），防止多人共用一份授权 |
| 离线失效 | 退款或设备被释放后，离线的 Mac 在 30 天离线有效期结束前仍可能保留 Pro；联网后立即失效 |
| 试用计时 | 联网时以服务端时间为准；离线时记录本地最后使用时间，系统时间被调回不会延长试用 |
| 改价 | 后台改价立即对新订单生效；已创建的收银台会话按创建时的价格结算 |

### 10.3 币种策略（D7）

**可以区分人民币和美元。** Pancake 创建收银台会话时必须指定币种，金额可以按币种分别设置，所以两种币种完全独立定价。

| | 人民币订单 | 美元订单 |
|---|---|---|
| 默认给谁 | 请求来源为中国大陆的用户 | 其他地区用户 |
| 可用支付方式 | 只有微信支付 | 银行卡、Apple Pay、Google Pay、微信支付 |
| 价格来源 | 后台的 CNY 价格 | 后台的 USD 价格 |
| 单笔范围 | ¥1–¥1,000 | $1–$10,000 |
| 固定手续费 | 无 | 银行卡等每笔 $0.50；微信支付无 |

规则：

- 服务端按请求来源地区返回默认币种，现有代码已经能取到请求国家。
- 购买和充值 sheet 上提供切换：「微信支付 · 人民币」/「银行卡 · Apple Pay · 美元」。中国用户想刷外币卡，或海外用户想用微信，都可以切换。
- 每个商品、每个充值包在后台分别填写 CNY 价格和 USD 价格；充值包的点数也可以按币种分别设置。
- 订单记录币种和实际金额，流水和账户页按原币种显示。
- 微信支付限额触发时（每个买家对同一商户每月累计 ¥1,000），人民币订单无法完成，客户端提示切换到美元。
- 美元订单用微信支付时，会先折算港币结算，用户实付的人民币金额可能与直接换算略有出入。收银台会显示实付金额。

## 11. 系统改动

### 11.1 服务端

1. **定价配置**：新增后台「定价」页，维护第 5 节全部配置项。新用户赠送从 `NEW_USER_CREDITS` 迁到同一处，保留环境变量作为兜底。
2. **订单表 `orders`**：订单号、用户、商品类型（pro / renewal / credits）、充值包、币种、金额、点数、状态（pending / paid / expired / refunded / refund_failed）、Pancake 订单号、checkout session、创建 / 支付 / 退款时间。
3. **Webhook 事件表**：记录已处理的事件 `id`，用于去重。
4. **授权表**：`licenses`（用户、状态、购买时间、更新截止日、来源订单）；`license_devices`（授权、设备标识摘要、设备名、最近使用、释放时间）；用户表增加试用开始时间。
5. **接口**：

```text
GET  /api/v2/pricing                       商品、价格、充值包（按地区返回默认币种）
POST /api/v2/orders                        { product, packID?, currency }，需 Idempotency-Key；返回 checkoutUrl、orderID
GET  /api/v2/orders/:id                    订单状态，供客户端轮询
POST /api/v2/payments/waffo/webhook        Pancake 回调，验签 + 去重
GET  /api/v2/account/entitlements          Pro 状态、试用、更新截止日、设备列表、签名凭证

POST /api/v2/account/devices/activate      激活当前 Mac
POST /api/v2/account/devices/:id/release   释放设备
```

6. **到账事务**：`order.completed` 时，把订单置为 paid、发放点数或授权、写入流水 `order:<订单号>`，放在同一事务里。

8. **退点**：任务变为 failed、expired，或在 queued 状态被取消时，写入流水 `refund:<任务号>`，金额为任务的 `credit_cost`，每个任务只能退一次。
9. **任务过期**：增加排队超时和最大重试次数，超出后置为 expired。
10. **流水原因枚举**：signup_bonus / purchase_credits / pro_bonus / widget_task / task_refund / order_refund / admin_adjust；接口返回 Widget 名称。
11. **余额约束**：现有 `credits >= 0` 约束需要放宽，以支持 8.3 的退款扣回。
12. **README**：更新「失败、取消或过期不退款」一段，补充支付配置说明。
13. **防滥用**：赠送记录增加设备标识摘要，同一设备只发一次；设备释放记录次数，按 30 天窗口限制；订单表对（用户、商品、pending）建唯一约束；创建订单接口接收 `expectedPrice`，不一致返回 `409 price_changed`。
