# 上线统计与免费终身 Pro

更新：2026-11-05。状态：数据库迁移、服务端／后台及官网已部署；客户端由用户构建验收。

## 运营入口

- 后台「收费指标」：官网访问到下载点击、正式环境 Pro 购买漏斗、关键点击、免费终身 Pro 发放及激活情况；支持最近 7 / 30 / 90 天。
- 后台「用户与授权」：按邮箱、姓名或精确用户 ID 搜索；每页 100 人，可继续翻页。为活跃的免费账户填写备注并点击「免费赠送终身 Pro」，确认目标邮箱后发放。原有付费 Pro 不覆盖。
- 「赠送记录」展示最近 100 次赠送的时间、备注、Mac 名额、审计 ID 与当前有效状态。用户登录后刷新账户并激活 Mac；离线使用仍受正常的签名授权刷新周期约束。
- 赠送为本地 Pro 及终身功能更新，不生成支付订单、不计收入、不附送云端点数。Mac 名额沿用后台 `deviceLimit`。积分继续独立发放。本次没有自动向任何真实用户发放授权。

## 事件与口径

| 事件 / 数据源 | 触发 | 统计用途 |
|---|---|---|
| 官网 `page_view` | 正式域名页面加载 | 标签页会话数，不是独立人数 |
| 官网 `cta_click` | 下载、导航、语言或币种点击 | 页面、语言、目标、位置的次数及会话数 |
| `trial_started` | 客户端启动，固定事件 ID 去重 | 试用起点 |
| `feature_click` | 已接入的本地工具及比较入口 | 功能交互次数，不代表操作成功 |
| `locked_click` | 本地工具权限阻断 | 免费用户的付费功能需求 |
| `trial_activity` | 试用工具交互、服务端受理 Widget | 保留原试用活跃统计，不当作产物交付成功率 |
| `login_prompt` / `login_success` | 登录界面展示 / 登录完成 | 同设备、同 journey 且成功晚于提示 |
| `pro_offer` | 同一 Pro 窗口首次展示 | 切档位、切币种、刷新不重复增加展示 |
| `checkout_click` | 点击 Pro / 点数购买 | 购买意图，不等同建单或付款 |
| `insufficient` | Widget 报价余额不足 | 同一任务确认流程一次，关联充值订单 |
| 订单表 | 服务端建单 / 支付通知确认 | 正式支付，不以支付回跳页作为付款成功依据 |
| 任务表 | 充值后再次确认并受理原任务 | 同账户、同 intent、匹配充值订单；取消不提交 |
| `admin_pro_grants` / 授权与设备表 | 管理员发放 / 激活 | 赠送、当前有效、当前激活分别计数 |
| `pro_redemption_codes` / 授权与设备表 | 兑换码生成、兑换、激活、到期 | 按终身／一年及批次分别计数，不计付费收入 |

官网访问 → 下载：区间内有页面访问的标签页会话为分母，之后点击下载的同会话为分子。同会话多次下载只计一次转化，点击表仍保留点击次数。下载点击不代表下载完成、安装、首次启动；没有跨网站与 Mac 的身份拼接。

Pro 漏斗：只统计正式环境，按区间内 `device_hash + journey_id` 去重，从展示开始关联后续点击、建单、付款。建单、付款必须属于点击时的同一账户；沙盒、模拟付款和免费赠送均不计付费转化。旧客户端没有 Pro journey 的展示不补算。付款数表示曾到账，退款另看原退款报表。

客户端、官网事件均为尽力采集，断网、页面退出或请求乱序可能低估漏斗。顺序采用服务端接收时间；无样本时不显示虚假的转化率。浏览器会话存储不可用时只关联当前页面。赠送的“已激活”为当前有效且有发放后激活的未释放设备，不是历史累计激活数。

## 数据边界

官网独立使用 `POST /api/v2/analytics/website`，仅接收枚举页面／目标／位置和随机标签页会话 ID；不发送 URL、查询参数、来源网址、邮箱、媒体、输入内容或账户身份。无第三方 SDK。尊重 DNT / GPC，预览域名和 localhost 不上报。数据库对事件去重，接口按 IP 的分钟哈希计数限流，定时清理 90 天前官网事件和 1 小时前的限流记录。

客户端沿用既有 `/api/v2/billing/events` 及设备哈希／账户关联，环境由服务端决定。生产漏斗不把测试环境的展示当作生产转化机会。隐私政策已补充产品统计说明。

## 2026-11-05：渠道 UTM 与统计区间（已部署）

- 官网只读取 `utm_source` / `utm_medium` / `utm_campaign` / `utm_content`，值统一转小写，仅接受 `[a-z0-9._-]{1,64}`；其他值（邮箱、网址、自由文本）直接丢弃，服务端再校验一次。带参数访问会覆盖当前标签页会话的渠道，并随后续页面访问和点击一起上报；随后用 `history.replaceState` 从地址栏移除全部 `utm_*`，避免被转发或收藏的链接造成重复归因。DNT / GPC 时不上报，但仍会清理地址栏。
- 后台「收费指标」新增「渠道（UTM）访问 → 下载点击」：会话归属区间内首次带参数的访问，无参数的会话归为「无渠道参数」。统计区间新增「今日（本地 0 点起）」和「自定义起始时间」；API 为 `?from=<ISO 时间>`（一年内、不晚于当前），仍截到埋点开始时间。
- 隐私政策已说明只采集这四项渠道参数。
- 正式渠道链接：
  - X：`https://glancepreview.com/?utm_source=x&utm_medium=social&utm_campaign=launch`
  - V2EX：`https://glancepreview.com/?utm_source=v2ex&utm_medium=community&utm_campaign=launch`
  - LinkedIn：`https://glancepreview.com/?utm_source=linkedin&utm_medium=social&utm_campaign=launch`
  - 新增渠道无需改代码，只需换一个符合规则的 `utm_source`。
- 已按顺序完成：备份 D1 → 应用 `0026_website_utm.sql` → 部署 Worker / 后台 → 构建并发布官网。线上专用 UTM 事件已验证只入库白名单字段，并已清理。

## 官网发行文案（已部署）

`website/static/build.py` 根据实际发布状态选择文案，页面中用 `<!--if:flag-->…<!--endif-->` / `<!--if:!flag-->…<!--endif-->` 标记：

- `beta`：`VERSION` 含 `-` 时为内测定位；正式版本号去掉「内测版 / beta」表述。
- `notarized`：对 `src/download` 中实际发布的 DMG 运行 `xcrun stapler validate` 和 `spctl`，两者通过才显示「已通过 Apple 公证」，否则显示放行说明。正式版本号（非 beta）搭配未公证 DMG 时构建直接失败。
- `sales`：公开快照中销售开启且可付款时，隐藏价格页「付款尚未开放」说明。

当前线上 DMG 为 10-22 的 `1.0.0-beta.1`（未公证），所以构建结果仍是内测 + 未公证文案，与安装包一致。改为正式版时，把公证后的 DMG 放入 `src/download`，更新 `VERSION`，重新构建即可切换。安装页的 Peek 权限说明已与客户端一致：只需「辅助功能」，「输入监控」无需单独授权，「完全磁盘访问」可选，权限可跳过。
